# Changelog

Изменения по всем серверам репозитория. Серверы версионируются
**независимо** — общей версии у репозитория нет; в заголовках записей указан
сервер и его версия. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

Подробности по своим серверам: [outlook-mcp](outlook-mcp/CHANGELOG.md).

## 2026-10-02 — grafana-mcp

- Добавлен сервер Grafana (сторонний, `uvx` из PyPI, `mcp-grafana` 2.0):
  дашборды, datasources, запросы к данным, алерты. Установочные скрипты
  `setup.sh` / `setup.ps1`, запуск с `--tls-skip-verify`, версия пинится в
  `mcp-versions.txt` (`GRAFANA_SPEC`).

## 2026-09-28 — zephyr-mcp 0.4.1

**Добавлено**

- `archive_test_cases` / `unarchive_test_cases` — архивация и восстановление
  тест-кейсов (`POST /rest/tests/1.0/testcase/bulk/archive` и
  `/bulk/unarchive` с массивом числовых id; ключи резолвятся через
  `GET /rest/tests/1.0/testcase/{key}?fields=id`). Проверено на живом
  инстансе: заархивированный кейс получает `archived: true` и скрывается из
  ATM-поиска.
- `delete_test_runs` — удаление тест-циклов
  (`POST /rest/tests/1.0/testrun/bulk/delete` с массивом числовых id; ключи
  резолвятся через `GET /rest/tests/1.0/testrun/{key}?fields=id`). Проверено
  на живом инстансе: удалённый цикл возвращает 404. Регистрируется только при
  `ZEPHYR_ALLOW_WRITE` **и** отдельном `ZEPHYR_ALLOW_DELETE` (по умолчанию
  выключен), помечен `destructiveHint`. Перед удалением проверяется формат
  ключа и что сервер вернул id именно запрошенного цикла.
- `update_test_case` принимает `status` — смена статуса тест-кейса
  (`PUT /rest/atm/1.0/testcase/{key}` с полем `status`). Проверено на живом
  инстансе: `Draft`/`Approved`/`Deprecated` → 200, невалидное значение → 400
  с читаемой ошибкой.

**Исправлено**

- `add_test_cases_to_run` падал с 500 на живом инстансе: реализация делала
  read-modify-write через `PUT /rest/atm/1.0/testrun/{key}`, а этот эндпоинт
  возвращает 500 на любой пейлоад (проверено curl: только `name`, только
  `items`, полный объект, на пустом и заполненном цикле). Теперь функция
  читает items рана и шлёт `POST /rest/atm/1.0/testrun/{key}/testresults` с
  JSON-массивом только новых ключей (`[{"testCaseKey":"..."}]`) — кейсы
  добавляются в цикл со статусом `Not Executed`, дубли уже присутствующих
  ключей пропускаются. Повторы внутри входного списка и ключи, отличающиеся
  только регистром, тоже схлопываются (каждый элемент POST создаёт отдельную
  execution-запись).

## 2026-09-25 — zephyr-mcp 0.4.0

**Добавлено**

- `add_execution_result` — проставить результат execution по тест-кейсу,
  уже входящему в цикл (`PUT /rest/atm/1.0/testrun/{key}/testcase/{caseKey}/testresult`).
  Обновляет существующую execution на месте, без дублей; кейс должен быть уже
  добавлен в цикл. `step_statuses` — опциональный список статусов по шагам
  (только `index` + `status`, текстового actual-result на уровне шага в API нет).

**Исправлено**

- `ZEPHYR_ALLOW_WRITE` парсился как fail-open: нераспознанное значение
  включало запись вместо безопасного дефолта. Теперь truthy-allowlist.
- `folder` в `create_test_case`/`create_test_run` не валидировался (только
  `create_folder` проверял путь) — теперь везде одна и та же проверка.
- `list_executions` кидает явную ошибку на пустое тело ответа вместо тихой
  подстановки `{}`, которая в `add_test_cases_to_run` могла привести к PUT,
  стирающему реальные items цикла.

## 2026-09-25 — zephyr-mcp 0.3.0

Правка и структура в Zephyr. Пишущие tools, как и ранее, доступны только при
`ZEPHYR_ALLOW_WRITE`.

**Добавлено**

- `update_test_case` — правка тест-кейса (`PUT /rest/atm/1.0/testcase/{key}`);
  обновляются только переданные поля.
- `create_folder` — создание папки (`POST /rest/atm/1.0/folder`); путь задаётся
  целиком в `name` и начинается со слэша.
- `create_test_run` — создание тест-цикла (`POST /rest/atm/1.0/testrun`); кейсы
  можно передать сразу через `items`.
- `add_test_cases_to_run` — добавление кейсов в существующий цикл. Реализация —
  read-modify-write через `PUT /rest/atm/1.0/testrun/{key}`, потому что замена
  items целиком не проверена.

## 2026-09-19 — zephyr-mcp 0.2.0

Запись в Zephyr. Чтение остаётся доступным без флага.

**Добавлено**

- `create_test_case` — создание тест-кейса (`POST /rest/atm/1.0/testcase`).
- `ZEPHYR_ALLOW_WRITE` — переменная окружения, по умолчанию запись выключена.
  Пока не включена значением `1`/`true`/`yes`/`on`, пишущие tools не
  регистрируются: клиент их не видит и вызвать не может. В отличие от
  `outlook-mcp`, где `EWS_ALLOW_WRITE` включён по умолчанию — Zephyr общий для
  команды, поэтому запись включается осознанно.

## 2026-08-16 — outlook-mcp 0.2.0

Запись в календарь. Почта остаётся read-only.

**Добавлено**

- `create_event`, `update_event`, `delete_event` — создание, изменение и
  отмена встреч. Изменять и удалять можно только встречи, где вы
  организатор.
- `EWS_ALLOW_WRITE` — переменная окружения, по умолчанию запись включена.
  При `0`/`false`/`no`/`off` пишущие tools не регистрируются: клиент их не
  видит и вызвать не может.
- `limit` в `list_events`.

**Изменено**

- `list_events` отдаёт `attendees_count` вместо списка участников — полный
  список остался в `get_event`. Иначе загруженный день не помещался в лимит
  ответа на стороне клиента и обрезался посередине. **Ломающее изменение**
  для тех, кто читал `attendees` из `list_events`.
- При изменении встречи уведомляются все участники, копия письма попадает
  в «Отправленные» — как при правке через Outlook.
- Ошибки подключения перестали маскироваться под проблему сети: HTTP 401/403
  отдаются как `authentication_error`.

**Исправлено**

- Экземпляр повторяющейся встречи терялся после переноса и становился
  недоступен для любых правок.
- Изменение экземпляра серии отклонялось Exchange.
