# Установка postgres-mcp (для сотрудников)

Скрипты настраивают MCP-сервер `postgres-mcp` (PostgreSQL: health-чеки, медленные
запросы, explain-планы, подбор индексов; сторонний код
[crystaldba/postgres-mcp](https://github.com/crystaldba/postgres-mcp)) для
Cline в VS Code. Запуск идёт через `uv`/`uvx` — **Docker не нужен**, прав
администратора/sudo тоже.

Что делает скрипт:
1. Находит `uv` (или предлагает установить — только с вашего согласия).
2. Спрашивает строку подключения к БД (`DATABASE_URI`, ввод скрыт — в ней пароль)
   и режим доступа (`restricted` — только чтение, по умолчанию).
3. Опционально спрашивает адрес корпоративной LLM-модели (можно пропустить
   по Enter — см. ниже).
4. Сохраняет всё локально в защищённый файл `.env` (в открытую сеть ничего не уходит).
5. Генерирует **лаунчер** рядом с `.env` и прописывает его в конфиг Cline —
   **без строки подключения и без версии пакета**: лаунчер сам читает `.env` и
   подтягивает актуальную версию из репозитория при каждом запуске сервера.
6. Проверяет, что пакет скачивается и запускается (`--help`).

Повторный запуск безопасен: существующий `uv` переиспользуется, секция в
конфиге Cline обновляется на месте (не дублируется), текущие настройки можно
оставить без изменений.

Понадобится: доступ в интернет (к `github.com`, `pypi.org` и `astral.sh`) и
**корпоративный VPN** для реального доступа к серверу PostgreSQL.

**Обновление версии не требует переустановки** — если версия пакета поднята
в `mcp-versions.txt` репозитория, лаунчер подхватит её сам при следующем запуске
сервера (см. корневой [README.md](../../README.md)).

## Режим доступа

Скрипт спросит, в каком режиме сервер работает с БД:

| | Что можно | Когда выбирать |
|---|---|---|
| `restricted` (по умолчанию) | только чтение | прод-БД и любые боевые данные |
| `unrestricted` | чтение, запись, DDL | только дев-базы |

Сомневаетесь — оставляйте `restricted`.

## Про LLM-модель (необязательный шаг) — **нажимайте Enter**

Последним вопросом скрипт спросит `OPENAI_BASE_URL` / `OPENAI_API_KEY`. Это нужно
только для **альтернативной** стратегии подбора индексов через LLM; основной
подбор индексов и все остальные инструменты работают без неё.

**Нажмите Enter и пропустите этот шаг.** В нашем контуре фича всё равно не
заработает: upstream жёстко запрашивает модель с именем `gpt-4o`, которое наш
корпоративный шлюз не обслуживает — он отвечает «No matching route found».
При пропуске переменные в `.env` не пишутся вообще.

Заполнять поля имеет смысл, только если ваш шлюз отдаёт модель именно под
именем `gpt-4o` (подробности и варианты — в [README сервера](../README.md)).

## Windows

1. Скачайте файл **`setup.ps1`**.
2. Правый клик по файлу → **«Выполнить с помощью PowerShell»**.
3. Если запуск блокируется политикой выполнения (ExecutionPolicy) — откройте
   PowerShell и выполните:
   ```powershell
   powershell -ExecutionPolicy Bypass -File setup.ps1
   ```
4. Ответьте на вопросы:
   - ставить ли `uv` (если не найден) — `y`;
   - при повторной установке — менять ли настройки (`y`/`n`);
   - введите `DATABASE_URI`, выберите режим доступа, при необходимости укажите
     адрес корп-модели.
5. Полностью перезапустите VS Code.

---

## macOS (только Apple Silicon, arm64)

> Intel/Rosetta не поддерживается.

1. Скачайте файл **`setup.sh`**.
2. Откройте Терминал в папке со скриптом и запустите:
   ```bash
   bash setup.sh
   ```
   Запускайте именно так — **не двойным кликом** (иначе сработает Gatekeeper/
   карантин).
3. Ответьте на вопросы (установка `uv`, строка подключения, режим доступа, корп-модель).
4. Полностью перезапустите VS Code.
5. Если PostgreSQL недоступен — проверьте, что подключён **корпоративный VPN**.

---

## Linux

1. Скачайте файл **`setup.sh`**.
2. Запустите:
   ```bash
   bash setup.sh
   ```
3. Ответьте на вопросы (установка `uv`, строка подключения, режим доступа, корп-модель).
4. Полностью перезапустите VS Code.
5. Если PostgreSQL недоступен — проверьте доступ в корпоративную сеть / VPN.

Нужны стандартные утилиты `curl`, `bash`, `python3` (обычно уже есть).

## Где что лежит

| | Windows | macOS / Linux |
|---|---|---|
| Настройки (`.env`) | `%USERPROFILE%\.postgres-mcp\.env` | `~/.config/postgres-mcp/.env` |
| Лаунчер | `%USERPROFILE%\.postgres-mcp\launch.cmd` (+ `launch.ps1`) | `~/.config/postgres-mcp/launch.sh` |
| Конфиг Cline | `%APPDATA%\Code\User\globalStorage\saoudrizwan.claude-dev\settings\cline_mcp_settings.json` | `~/Library/Application Support/Code/...` (macOS) / `~/.config/Code/...` (Linux) |

## Если что-то пошло не так

- **`uv`/`uvx` не найден после установки** — перезапустите терминал (PowerShell)
  и запустите скрипт ещё раз.
- **Ошибка скачивания пакета** — проверьте доступ к `pypi.org` (интернет, прокси).
- **Cline не видит сервер** — полностью закройте и откройте VS Code; проверьте,
  что сервер `postgres-mcp` включён в списке MCP Cline.
- **БД недоступна / ошибки подключения** — подключите корпоративный VPN, проверьте
  хост и порт в строке подключения.
- **Сервер отказывается выполнять запись** — это `restricted`-режим, так и задумано.
  Запустите скрипт снова и выберите `unrestricted` (только для дев-базы).
- **Ошибка «модель не найдена» при подборе индексов через LLM** — корп-эндпоинт
  не принимает имя модели `gpt-4o`, которое upstream запрашивает жёстко.
  Основной подбор индексов при этом работает.
- Строка подключения и токен нигде не выводятся в лог и не пишутся в открытом
  виде в консоль. Если нужно их сменить — просто запустите скрипт снова и
  ответьте `y` на вопрос об изменении.

При других проблемах обращайтесь к администратору postgres-mcp.
