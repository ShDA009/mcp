## [0.2.0] — 2026-08-16

Первая версия с записью в календарь. Почта остаётся read-only.

### Добавлено

- **`create_event`** — создание встречи. Время принимается как ISO-строка;
  без указания смещения читается в таймзоне ящика (`OUTLOOK_MCP_TIMEZONE`),
  со смещением — как передано. Участники задаются **только email-адресами**;
  если известно имя, сначала `resolve_person`. Поддержаны события на весь
  день (`all_day`), где `end` — последний день включительно.
- **`update_event`** — изменение встречи (только организатором). Меняются
  лишь переданные поля. Передан один `start` — встреча переносится с
  сохранением длительности; передан один `end` — меняется длительность.
  Списки участников заменяются целиком, `[]` очищает список.
- **`delete_event`** — отмена встречи (только организатором).
- **`EWS_ALLOW_WRITE`** — переменная окружения, по умолчанию запись
  включена. При `0`/`false`/`no`/`off` пишущие tools **не регистрируются**:
  клиент их не видит и не может вызвать.
- **`limit` в `list_events`** — ограничение числа событий в ответе
  (сервисный слой поддерживал его и раньше, tool не пробрасывал).
- **`PermissionDeniedError`** (`permission_denied`) и
  **`ResultTooLargeError`** (`result_too_large`) — новые коды ошибок.

### Изменено

- **`list_events` больше не отдаёт список участников** — вместо него
  `attendees_count`. Полный список остался в `get_event`. Причина: день из
  9–13 встреч по 10–20 участников не помещался в лимит ответа на стороне
  клиента и обрезался посередине, из-за чего события в середине дня были
  недоступны. Размер ответа за день сократился примерно втрое.
  **Ломающее изменение** для тех, кто читал `attendees` из `list_events`.
- **При изменении встречи уведомляются все участники**, и копия письма
  сохраняется в «Отправленных» — как при правке через Outlook. Уведомить
  только затронутых правкой и одновременно сохранить копию через один
  EWS-вызов нельзя; выбрана копия.
- **Поиск встречи по устаревшему `event_id` убран.** Раньше сервер
  сканировал календарь, пытаясь заново найти item. На ящиках с
  повторяющимися встречами без конечной даты это занимало десятки секунд, а
  иногда отклонялось Exchange. Теперь сразу возвращается `item_not_found` с
  подсказкой вызвать `list_events` и взять свежий `event_id`.
- **Ошибки подключения перестали маскироваться под проблему сети.** HTTP
  401/403 отдаются как `authentication_error` с кодом, слишком большой
  результат — как `result_too_large`, остальные транспортные ошибки
  сохраняют исходный текст.

### Исправлено

- Экземпляр повторяющейся встречи терялся после переноса: Exchange меняет
  его тип на `Exception` и выдаёт новый id, а поиск по календарю таких
  событий не видел.
- Любое изменение экземпляра серии отклонялось Exchange
  (`ErrorInvalidPropertySet`, поле `calendar:UID`) — обновление отправляло
  поля, которые на экземпляре менять нельзя.
- Ответ Exchange «слишком много объектов» на ящиках с бесконечными сериями.

### Примечания

- `event_id` устаревает после любого изменения встречи — своего или чужого.
  На `item_not_found` нужно перезапросить список и повторить с новым id.
- Повторяющиеся встречи создавать нельзя; правится только конкретный
  экземпляр, не серия целиком.
- Занятость времени при создании и переносе не проверяется — для этого
  `find_free_slots`.
